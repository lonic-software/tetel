## What this design delivers

An author who sets one key, `verify.typed_model`, to a TypeSafe model gets Jev on the legs of the mint-time verifier where it was measured to hold its own: a gate that skips the LLM check on subjects with nothing to find — 58% of the check's cost on `fact`, 21% on `claim`, no adjudicated defect skipped — and, on `claim`, Jev in place of the LLM's classify call, which is about half of what a `claim` verification costs. The check leg itself stays an LLM on OpenRouter. Which legs a verb may send to TypeSafe is a table in source, the refuter included, because routing follows the model value and every model-valued key is otherwise a typed leg waiting to happen. A skipped mint says `gated` and runs nothing else, the version that answered is printed, and a missing TypeSafe credential is `unauthorized`. Because the savings are the point, they have to be visible in the place that reports them: TypeSafe states tokens rather than a price, so a typed call is priced in source from the published rate instead of counting as free. For anyone who sets no `typesafe/` value at all, nothing changes: `typed_model` and the literal leg stay off by default, and turning either into a default is owed measurement covering every table row it would switch on — one joint run of the shipping configuration on `claim`, and a second on `fact`, both judged on the design's steering-hazard line as a rate.

*cites: C11, C12, C13, C17, C18, C19, C23*

## Where Jev can and cannot go

TypeSafe's Jev is not a cheaper LLM. It answers typed questions — a probability, a choice among options the caller names, a position on a scale the caller orders — and returns nothing else. That settles the one question this design cannot negotiate: the check leg, whose whole product is a finding quoting the author's clause and the evidence against it, stays an LLM on OpenRouter. Everything Jev takes on below is a leg whose answer was already a choice, or can be made one by moving the string work into code. One caveat on the evidence for that: no harness keeps a raw response, so the endpoint's shape rests on a live call this memo made rather than on a file in the tree.

*cites: C2*

## What was measured

Every leg was measured on the corpora and adjudications the LLM legs were graded on. Each leg was measured alone, with the others left as they ship: no run has measured the configuration this design would ship, where the gate, Jev classify and Jev literals run together. That limit shapes the recommendation below more than any single result does.

*cites: C4, C5, C6, C14*

**The refuter.** Asked whether a proposed `fact` finding really disagrees with its evidence — the question `REFUTE_SYSTEM` already asks as a choice of three words — Jev lands between the two LLM refuters on the same findings, at a hundredth of their cost and under a second.

*cites: C3*

**The gate.** Asked before the check leg whether a subject is worth checking, Jev barely helps when the question is "is anything here wrong" and helps a great deal when it is "which of these units is wrong, or none" — the units then compete for one probability, and a clean subject puts it on NONE. That presentation saves 58% of the check leg's cost on `fact` and 21% on `claim` without skipping a subject that carried a real defect, and on `claim` it also removes 4 of the 13 adjudicated false alarms. On `prose` nothing separates. The thresholds are fitted to the same few positives they are scored on, so "none skipped" is an in-sample result with a margin, not a guarantee.

*cites: C4*

**Classify.** `split`'s first call only sorts the author's own words into current, proposed and argument, so the sorting can be mechanical and the labelling a choice. With Jev's labels in front of the same LLM check, the `claim` verb raises the same number of correct warnings for 39% of the cost — because the classify call, which reads the claim alone and was assumed to be the cheap one, is about half of a `split` verification's spend. One question stays open: counted per claim, Jev's arm flagged 8 sound claims to the LLM's 6, either side of the design's line of 7 — a gap smaller than the same LLM configuration's own movement between August and today, so these runs cannot say which side of the line Jev classify belongs on.

*cites: C5, C8, C9*

**Literals.** The literal leg already decides every factual part of its finding in code; with code also proposing the candidates, Jev's judgement matches the LLM's at a sixth of the cost and is far more stable. The leg's own problem is unchanged: added to today's check it costs attention the steering-hazard line cannot spare. Behind the claim gate it fits.

*cites: C6*

**Which Jev.** The measurements name the alias `jev-latest`. The endpoint resolves that alias to a version and says which in every reply, and no harness kept the answer — the client discards the reply's `model` field before anything can, and one of the five harnesses, the one behind the classify comparison, records no model at all, not even the alias. No tracked file in the tree contains the string `jev-1.`; the only paths that do are this memo's own rendered output, which has it because this memo wrote it. The design has to keep the version, and the one it proposes to compare against comes from a spike whose response was not recorded either, which makes that constant the weakest thing here. The first implementation task is to make it checkable.

*cites: C7*

## The design

**One key, and a vendor that routes.** An author turns Jev on with `tetel config verify.typed_model typesafe/jev-1.13.0`. The vendor half `typesafe` is what sends a call to TypeSafe instead of OpenRouter, so the existing model-name syntax needs nothing new, and the credential comes only from TYPESAFE_API_KEY in the environment, exactly as OPENROUTER_API_KEY does. Routing on the value rather than the key it came from has a consequence worth stating plainly: `verify.refuter_model` already accepts a `typesafe/` value, and the moment it holds one it is a typed leg too, whether or not `typed_model` is set. That is why the table below is written over legs rather than keys. There is deliberately no `verify.provider`: the check leg stays on OpenRouter whatever such a key said, so it would name a choice nobody can make. `verify.model` refuses a `typesafe/` value outright, and the refusal already holds on both paths — the same acceptance test runs when a value is set and again every time one is read, so a hand-edited config file cannot smuggle Jev into the check leg. What it can do is produce a bad diagnostic: the rejected value is dropped on the way through and the author is told the key is not set, in front of a file where it visibly is. So the message gains an arm that names the scope and the value it refused — computed where the workspace directory is still in hand, which is `settings()` and not the function that prints it, since the case the arm exists for is a workspace-scope file and the printer has no path to look it up with. A second provider also has to be paid for in the arithmetic. The code that totals what a verification spent reads a price the provider states, and TypeSafe states tokens instead — which is the one part of the endpoint's shape this memo does not have to take on the word of an unrecorded live call, because a committed benchmark file stores a Jev reply's usage object verbatim: two token counts, no cost key. Left alone, a typed leg would cost zero in the one place a reader checks. So the published input rate ships as a dated constant and a typed call is priced from it, the same arithmetic the benchmark harness already performs, which agrees with the envelope if the envelope does carry a price and is the only thing that works if it does not.

*cites: C10, C11, C23*

**What the key turns on is decided per verb, in source.** On `fact`: a gate before the check, and the refuter may be Jev. On `claim`: a different gate, Jev classify, and Jev judging literals if literals are on. On `prose`: nothing. Each cell is what was measured on that verb — including the cells that say no, which are a bad measurement on `prose`'s refuter and no measurement at all on `claim`'s. Nothing measured on one verb is carried to another: `fact` shares its classify prompt with `claim`, the literal leg takes no verb, and the refuter takes none either, so without an explicit table any of the three would silently run a Jev leg nobody measured there. The refuter is the sharpest case, because it is the one leg an author can turn typed without touching `verify.typed_model`: enforcing its row means `refute_findings` learns the verb it does not take today. Each leg also ships with the presentation it was measured with, splitter and score included, because the numbers belong to the presentation.

*cites: C12, C15*

**A gated mint says it was gated.** The gate asks first, before classify. A subject it skips reports a new status, `gated`, rather than `ok` with nothing in it — the whole status vocabulary exists so that an empty result cannot pass for a clean one. Nothing else runs on that subject either, the literal leg included, and the reason is structural rather than a matter of price: a record carries findings at all only when its status is exactly `ok`, so a literal raised on a gated subject would be dropped before the author saw it, and delivering it would mean making `gated` a second findings-emitting status. What that costs is measured on one verb only. On `claim` it is one claim in fifty, with the Jev literal leg behind a gate that skips 27% of subjects. On `fact` the leg being suppressed is the LLM one, the gate skips 60%, and no run here puts an LLM literal leg behind any gate. That price is owed, and owed by its own run over the `fact` corpus rather than by the joint run below, which is over claims and cannot answer for a different verb, a different gate and a different literal leg — a debt assigned to it would have no creditor. What stands in for that run meanwhile is the default: `verify.literals` is off, so a `fact` verification as shipped puts only the check leg behind the gate, and the check leg's price is the measured one. A gate that fails never skips anything: the check runs and the response says `gate_incomplete`. The gate's probability is not shown to anyone.

*cites: C13*

**Nothing changes for anyone who sets no `typesafe/` value.** That is the honest statement of the default, and it is not the same as "`verify.typed_model` unset", since a typesafe refuter routes on its own. `verify.typed_model` is unset by default, and `verify.literals` stays off even when it is set. Neither is one verb's decision, and that is what makes both of them slow to flip: a single key turns on a table with three rows, so the evidence has to cover the rows, not the key. `verify.typed_model` waits first on one joint run of the configuration that would ship — gate, Jev classify, check and Jev literals together, on `claim` — showing the sound claims it flags stay under the design's line, read as a rate of 11.3% against a denominator the run names rather than as a count borrowed from another corpus. That run is also the only thing that can test the gate's headline result where it matters on `claim`, since the warnings the threshold was fitted against were raised under the LLM classify call and a gated subject is never classified at all. It does not test the `fact` row at all, and flipping the key turns that row on too. The `fact` gate is better off on one count — it was measured in the order it would ship — and no better off on the other: its threshold is fitted on twelve adjudicated positives with nothing held out, so "none skipped" is an in-sample result there as well. Evidence that it holds off its own sample is owed before the flip, and the `fact` run below is where it comes from. `verify.literals` waits on both runs for the same reason, the same joint run answering for `claim` and the `fact` run for the LLM literal leg behind that gate. One flag means the weaker case governs, so both stay off until the evidence covers every row they would switch on. Every figure above that joins two legs was assembled from runs of one leg each.

*cites: C19, C14*

**The refuter can be Jev on `fact`, and the table is what keeps it off its own judgements.** `verify.refuter_model` takes a `typesafe/` value today and asks REFUTE_SYSTEM's three-way question as a choice. It runs on `fact` alone, and for a measured reason rather than an absent one: Jev was also run as the refuter on `prose`, where it keeps 13 of 44 adjudicated findings at 31% precision and loses 2 of 6 true catches, against 8 of 10 at 80% on `fact`. `claim` is the verb with no Jev refuter run at all, which is its own reason to leave it alone. `refute_findings` gains the verb it does not take today to enforce that. On a verb whose row refuses it, the typed refuter runs nothing — no quiet fall back to the default LLM refuter, which would spend on a model the author had just replaced — and the response omits the refuter name entirely rather than printing one for a leg that never ran, carrying instead a key that names the verb and the unused value. That has to be said because the nearest existing path does the opposite: the rule that a model may not refute its own judgements already declines to run and reports itself into telemetry the author never sees, under a refuter name that is printed anyway. An earlier draft of this memo extended that rule to the typed model and called its scope right as it stands. Both were wrong, and the mistake is worth keeping visible. The rule has no scope — it returns every finding it was handed, and it is handed the check leg's findings with the literal leg's appended. Extended, it would have deleted the whole refutation leg in the configuration an author is most likely to write, one typesafe model on both keys on `fact`, taking the 80% result this row rests on with it, and saying so only into the telemetry nobody reads. So the rule is left exactly as it is, and what actually guarantees that no model judges its own findings is the table: on `fact` the typed model runs the gate, which produces no findings to judge, and on `claim`, the one verb where it judges literals, its row permits no typed refuter. A refuter call that fails is reported as `refuter_incomplete` instead of passing unrefuted findings off under a printed refuter.

*cites: C16*

**The version is part of the result, and the budget has to be able to say two numbers.** The thresholds are fitted to one version's probabilities, so the code records which version was measured, prints the one that answered, and says `typed_model_unmeasured` when they differ. Where that flag sits is part of the decision: beside the keys a response always carries once a typed leg has run, and pointedly not beside the one qualification the response carries today, which is emitted only under an `ok` status. Put there it would vanish on exactly the mints that most need it — a gated one, where the drifted gate was the only call made and it suppressed the check under a threshold fitted to a version that may no longer be answering. A missing TYPESAFE_API_KEY is `unauthorized` — naming the variable, and raised only when a leg that would actually run needs it, so that a typesafe refuter set on a verb whose row does not use it cannot fail a whole verification. Never a quiet fall back to the LLM legs under a printed typed model. The budget needs real work: today one constant is multiplied by one call count, which cannot describe a run that is LLM legs at sixty seconds and typed legs at about one, and the count is now verb-dependent while the function computing it has no verb in scope. Splitting that count is not local to the budget, because a second reader compares it against the attempts a verification actually made, to report which runs retried. Attempts are counted once per provider call whoever the provider is, so a count that covers the LLM legs alone would report every gated mint on an unrefuted workspace as a retry — the failure that metric's own comment exists to forbid. It compares against the total of the two counts instead, which is as much as one attempt counter can support.

*cites: C17, C18*

## Rejected alternatives

Jev as the check model, and a `verify.provider` key that would pretend to offer it; one key per typed leg; a gate asked of the whole note; gate criteria rewritten for recall; the capture placed before the author's text; a gate on `prose`; and a Jev probability surfaced to the author as a confidence. Each is rejected on a measurement or on a property of the code, not on taste, and the numbers are above.

*cites: C2, C11, C20*

## Implementation surface and what must hold

The change lives in src/verify.rs, src/config.rs and src/mcp.rs, and docs/verify.md is edited in six places, not one. Five functions change and three data structures. Four of the eight are declared and censused below; the other four are named here instead, and for one reason in every case. A censused search takes no word boundaries, and the eval corpora under scripts/verifier-eval/ quote tetel memo prose, so a common symbol drags megabytes of corpora into a capture that can never be revised and ships beside the memo. `block` is the extreme — 187 files, five megabytes — and `Record` is the same effect at a twentieth of the size: twenty matching lines with word boundaries, twelve hundred without. The counts have since been re-derived independently, by counting matches without capturing them; the byte totals have not, for exactly the reason they state — checking a byte total means making the capture it describes — and the nearest an independent pass could get was a raw sum short by the `path:lineno:` prefix tetel's own output carries. `run` and `spawn` are untenable for the ordinary reason. That is a real gap — four of the eight symbols are invisible to the section that exists to make them visible, because the corpora a design was measured on live in the worktree the design modifies. It is not, as an earlier draft of this memo claimed, that the section only takes functions: it takes anything, and this memo had already declared a struct in it. `block()` is where this design's response shape lands: the credential diagnostic, the new `typed_model` and resolved-version keys, and the refuter name that stops being printed unconditionally are all inside it, and an earlier draft said it was untouched. `spawn()` is where the result lands — the only route from a verification's return value into a logged record. `report_text` is the one nobody expected: splitting the per-call budget by provider changes a function whose other caller is the report that says which runs retried, and reading that as a threading problem rather than a fifth modified function is how it stayed off the list. The `Status` to change is the verifier's, not the ledger's enum of the same name. The prose that goes stale is mostly operator-facing, which makes it the sharper half of the work: docs/verify.md introduces its status table with the word *always* over a closed list of eight that gains a ninth; states in the `unauthorized` row that `detail` names one of two things, when this design adds two more; lists the settings every response echoes, one of which becomes conditional and two of which are new; says that echo is the only place the refuter in force appears, which is exactly what a suppressed refuter breaks; and prints the default timeout arithmetic as a formula this change replaces — twice, once in the settings table and once again in a paragraph below it, which is how an earlier enumeration of these passages came up one short. Five comments in the source go stale with it, including the one at the head of `run()`'s body that calls the classify/check cost ratio unmeasured, and two summaries in the config module's key table that `tetel config` prints to the author deciding what to set: one repeating the same default timeout arithmetic a third time, one repeating the unmeasured-ratio claim. Two more are wrong today rather than made wrong here, and both sit in the lines this change edits: `refuter_model`'s doc comment claims the key is absent when unset, while the code emits it as null; and the config module's comment on what a key accepts says the acceptance test never runs on a read, which is exactly the belief this design had to correct. Both move too, because leaving a comment the design's own reasoning disproves is how the next reader inherits the mistake. This claim ships out of proof, which `check` reports as a failure, and the reason is worth stating rather than leaving to be inferred. Five passes graded it and every one returned an enumeration short an item or a citation off by one — a missing `docs/verify.md` passage, a missing pair of config summaries, a struct described by three of its eight fields, three line numbers off by one. Each finding was folded back into the wording, which puts the claim out of proof again, and a sixth pass would most likely do the same. What is ungraded is therefore the wording of the last round of corrections, not the content: every location named above has been checked at source by someone other than the author, and the claim is the most examined thing in this memo rather than the least.

*cites: C21, C8*

Eleven invariants carry the design, each with the revert its test must turn red: no typesafe value anywhere means unchanged; skipped means `gated` and nothing else runs; a failed gate means checked; `verify.model` cannot be Jev, and a config file that says otherwise is told so rather than told the key is unset; one typesafe model on both keys still gets its findings refuted, because none of them came from that model; a credential is demanded only by a leg that runs, and its absence is `unauthorized`; a different version is flagged, on a gated mint too; each verb runs only its own row, the refuter included, and no row puts one model on both a finding-producing leg and the refuter; a typed refuter its row does not permit runs nothing and prints no model name; a typed leg is not counted as a retry; and a typed leg costs more than nothing. Six of the eleven carry more than one revert, because the first wording of each would have gone green while the property it advertised was false — two because the refuter routes on its own value and answers to no verb, one because it tested the prompt rather than the config file, one because it named a key without saying where in the response it appears, one because a diagnostic can be computed in a place that cannot see the file it is about, and one because moving a key out of a literal changes the response for a configuration that has no typesafe value in it at all. That is the argument for writing an invariant over the state that matters rather than over the key that was on your mind. Their demonstration, green with the fix and red under the revert, is owed when the code exists.

*cites: C22*

| C23 | Decision — a typed leg's cost is priced in source, not left at zero. This design is sold on cost, and the mechanism that reports cost cannot see a typed call. `tel.cost` accumulates `v["usage"]["cost"]` from the provider's own envelope, in exactly one place, defaulting to zero under a comment saying it is "Whatever the provider says it charged" and is "Absent on providers that report none". TypeSafe is such a provider, and this is the one part of this memo's picture of the endpoint that does not rest on the live call alone. A committed benchmark file stores a Jev reply's `usage` object verbatim: scripts/verifier-eval/fact_refuted_jev.json, at records[1].findings[0].refutation, carries `usage` = {'input_tokens': 3332, 'output_tokens': 61} — two keys, no `cost` — inside an object that is unmistakably a typed refutation (`verdict`, `p_correct`, `choice_confidence`, `choice_probabilities`). `jev.ask()` keeps `answers` and `usage` and composes neither, so what is on disk is the endpoint's own usage object. What stays witnessed by the live call alone is the rest of the envelope — the three top-level keys C2 describes, and the `model` field C7 rests on — because no harness stores a raw response, and that is a narrower gap than an earlier draft of this claim admitted, which said nothing on disk could confirm any of it. The tree's other behaviour is consistent and hard to explain otherwise: scripts/verifier-eval/jev.py prices every Jev figure locally, recording the published rate in its own header as "input $0.042/MTok, output free", defining `USD_PER_INPUT_TOKEN = 0.042 / 1_000_000`, and computing `cost = usage.get("input_tokens", 0) * USD_PER_INPUT_TOKEN`, which is work nobody does against a provider that reports a price. The decision holds on the weaker reading too: if the envelope does carry a cost, pricing from the rate agrees with it, and if it does not, pricing from the rate is the only thing that can. Shipped without it, every typed leg would contribute exactly 0.00 to `Record.cost`, and `report_text`'s "cost — total, each" line would report a mint that made a gate call and a refuter call as having spent what the LLM legs alone spent. That is wrong in the direction that flatters this design: the savings it claims would be invisible in the one place a reader looks for them, and a workspace that ran typed legs and no LLM legs at all would report zero. So the input rate ships as a constant beside the endpoint constant, and a typed call is priced from the `input_tokens` its reply carries, by the same arithmetic jev.py already performs. Pricing from input alone is complete rather than partial only because output is free at that published rate, and the constant carries that condition with it: a rate that began charging for output would make this arithmetic undercount in the same flattering direction, and the reply does carry `output_tokens` to multiply if it ever does — the stored usage object shows both fields present, so the undercount would be silent rather than visibly absent. This inherits the weakness C17 names for the version constant, and inherits it more sharply: a published price is a number that lives outside the tree, changes without notice, and — unlike the resolved model version — is not echoed in any reply, so nothing in a response can ever detect that it has drifted. The constant therefore carries the date it was read, which is something the harness it is taken from does not record, so the date comes from this memo rather than from jev.py; and a typed leg's cost is documented as computed from a rate rather than reported by the provider. Leaving it at zero and documenting that instead was considered and rejected: a zero cost is indistinguishable from a leg that did not run, and this design's whole argument is arithmetic about what the legs cost. Recording one raw reply into a committed file answers what is left of this premise and C17's constant at the same time, which is why C17 makes it the first implementation task. | OWED |
