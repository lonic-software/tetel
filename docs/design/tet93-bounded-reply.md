# TET-93 / TET-56: a bounded reply

This memo decides what a bounded tetel reply is, and applies that decision to the three replies TET-93 names: `look`, `fact` and `query`. It is the shared decision that queue items A2 to A7 wait on. `run` (A5) and `check` (A6) are held under the same bound here only by a backstop; shaping them properly is their own work, as is what the exclusion note should contain (A4) and how much a capture may store (A12). All of these are deferred explicitly, in the last section. Everything below was read against one pinned worktree.

*cites: C1*

## The defect, and the threshold behind it

The stub is Claude Code's, not tetel's. Past a size threshold it writes an MCP reply to a file and hands the model the path instead. A grounder or attacker restricted to tetel's own tools has no way to open that path, so the reply is simply gone, and nothing in the stub says what was in it. Both tickets had to infer the threshold from spills. It no longer needs inferring: the installed binary sets it at 50,000 characters for an unannotated MCP tool, and lets a server set its own per tool through an annotation. That changes the premise TET-56's f3 memo was built on, which held that tetel cannot learn the caller's cap and so has to guess below it. Tetel still cannot read the cap at run time, but for the client this loop runs in, it can declare one.

*cites: C2*

Today tetel measures none of its replies, so every verb that reads the tree or lists the workspace can cross the threshold. TET-93's `fact` case needs correcting on one point. `fact` does not echo the output it mints, as the ticket's proposal assumed; the only captured text it can carry is evidence that `verify`'s findings quote. Its size comes from `folded`, which repeats each pending entry's label in full, and a search's label ends in the exclusion note that lists every git-ignored path. So the 130k-character `fact` reply was TET-92's defect surfacing through `fact`. It was not an output echo.

*cites: C3*

## The budget, and the threshold tetel declares

A bounded reply is one whose size is at most `REPLY_BUDGET`, 32768 UTF-8 bytes. Size means the content text plus, when there is one, the serialized `structured_content`. A structured reply carries its JSON in both fields, and this design could not establish whether Claude Code counts one field or both, so the budget counts both, and a structured reply gets about half of it for its JSON. Bytes are the unit because they are what tetel can count cheaply, and they are safe: JavaScript's string length never exceeds UTF-8 byte length. 32768 is under the 50,000 characters an unannotated tool gets, so the budget alone keeps tetel clear of the spill, however the client measures and whether or not it reads what tetel declares.

*cites: C6*

Tetel also declares its own threshold, `_meta["anthropic/maxResultSizeChars"] = 100000` on every tool it lists, which rmcp can already emit. The declaration is headroom and not permission to send more. The budget stays at 32768, and 100000 covers the case this design could not rule out: that Claude Code counts `content` and `structured_content` together, and `structured()` puts the same JSON in both. The 500000 ceiling was not taken, because a reply that is never spilled still costs the caller its context. One residual risk remains open: a per-tool-name override inside Claude Code, whose source was not traced, would win over the declaration. The budget is what protects against that.

*cites: C7, C4, C5*

## One enforcer: the backstop in `call_tool`

"Every reply is bounded" cannot rest on each verb remembering to bound itself. The next verb, or the next field added to an existing one, would break it silently. `call_tool` is written by hand so that every tool call goes through one place, and that makes it the enforcer. It measures every outcome it returns, including its own stale-build refusal, and reduces an over-budget result in two steps. If the content text alone fits, only `structured_content` is dropped: `structured()` already put the same JSON in the content, so nothing is lost and no marker is needed. Otherwise the reply becomes text only. It carries any `verify` object whole, because a finding in it is already marked delivered and cutting it would lose the finding. After that comes a prefix of the rest, cut at a line boundary, and then a marker, all of it inside the budget. The marker states the bytes shown against the total, and that it was the reply that was cut. It deliberately says nothing about the capture: only the verb knows whether its capture is whole, and once A12 bounds storage it may not be. A protocol error's message is cut the same way, so no outcome is exempt. The backstop is a floor, and it is not how a verb is supposed to answer: `look`, `fact` and `query` shape their own replies below, and a reply the backstop has to cut counts as a defect in the verb that produced it. Until their own items land, `run`, `check`, `claim` and `prose` are held under the bound by the backstop alone.

*cites: C8, C5*

## Shaping the three verbs TET-93 names

**`look` on a file.** A `look` whose selection (the whole file, or the requested lines) is over the budget pages instead of spilling. The reply carries whole lines from the start of the selection up to the budget, and it ends by naming the next range to ask for. The capture is narrowed to match: the pending entry holds only the lines returned, and its label names that range, so a fact minted from it never claims the author saw more than was shown. The CLI's `look` shares the same dispatch and pages the same way, so a fact means the same thing whichever surface minted it. Refusal was rejected because it gives the author nothing to work with. An outline (signatures and headings) was rejected because it needs a parser for every language tetel might open, and because an outline is a summary, not the text a fact is minted from.

*cites: C9, C3*

**`look` with `grep`.** A search cannot page the way a file does, so this follows TET-56 f3. The capture keeps what it keeps today, every match line after tetel's own exclusions, and whether that storage is bounded is A12's call. The reply carries whole match lines up to the budget. A first match line that is over the budget by itself is cut rather than dropped, so a search never answers with nothing. The shortfall is stated in both the reply and the label. The exclusion note counts against the budget too. When it does not fit, it falls back to counts, and what it should list at all is left to A4. Paging a grep is deferred; for now the marker points to a narrower root or pattern.

*cites: C10, C3*

**`fact`.** Two routes let TET-93's reply overflow, and there is one trap in closing them. The first route: each attention entry's guidance repeated every extent label of the fact, uncut, once per path the note names outside its extent. That is fixed in `scope::advice` itself, which now lists at most four labels, each cut, and a count, so the CLI and MCP keep sharing one text. The second route is `folded`, which is bounded like the other lists: each entry is cut to `ENTRY_CAP` (1024 bytes), then whole entries are kept until the budget, and whatever is left over becomes a count with a pointer to `query facts`. The trap is `verify`. A finding is marked delivered while the reply is being built, and no surface prints a delivered finding's text afterwards, so a finding that shaping drops is gone for good. So shaping follows a fixed priority. `verify` comes first and every finding is shown: the quoted text shrinks as the number of findings grows, never the number of findings. Its allowance is the same in every verb, so the backstop can always carry it whole. Then attention, then `folded`, then refusals. There is a floor at about a hundred findings in one verification, where even their fixed fields cannot fit. At that point the reply shows what fits, states how many findings it withheld, and still commits the delivery. Holding the delivery back would be the gentler-looking choice, but the delivery cursor is a single position, so it would block every later verification in the workspace. The withheld findings are the one loss this design concedes, until the deferred partial delivery cursor exists. Minting is not affected; only what the reply reports is shortened.

*cites: C11, C3*

**`query`.** Listings page, with two parameters that each mean one thing. `from` is always an id: the record a listing starts at, or the dependent `deps` starts at. A trailer names the next `from`. Labels and text in a listing are cut to `ENTRY_CAP`. A fact whose extents alone would overflow a page gets a page to itself, with its surplus extents counted, and the count names the call that reads them: `id` with `extent_from`. Asked for by `id`, a fact comes back with its labels uncut and its extents paged by `extent_from`, and a claim, which has no extents, comes back whole. A single label longer than the budget is cut, and says so. The CLI gets the same flags, so the two surfaces do not diverge.

*cites: C12*

## Deferred, and how the slices are proven

Each of these stays with its own queue item: shaping `run` (A5) and `check` (A6), what the exclusion note should contain (A4), how much a capture may store (A12), `query prose --ids` (TET-66), paging a grep, and a partial delivery cursor for verify findings. Until they land, the backstop is what bounds their replies. This memo fixes what every one of them has to fit under, the budget. The backstop's marker speaks only about the reply, so A12 is free to bound storage. When it does, the verb that captured says so in its own label and reply.

*cites: C13*

Each slice ships with its tests, and each test has to be shown red against a revert of the change it guards. The annotation test compares two exact sets, the tools listed against the tools annotated, so that a new tool without the annotation fails it. The backstop test counts the marker inside the budget, and includes an under-budget contrast to show that shaping never touches a reply it does not need to. The grep test checks the reply and the capture separately, because the defect it guards against is a reply that fits the budget while the capture has quietly lost matches. The `fact` test builds the attacker's case, big folded labels plus a note that names paths outside its extent, because a `fact` test without attention entries passed while the overflow was still open. The last test says the backstop never fires for a verb this memo shapes, which is how "a cut reply is a defect" gets enforced.

*cites: C14*
