# TET-29 design: the transplant premise inventory, and what "transcribed verbatim" must mean in a tool where evidence is captured

All code observations in this memo were taken against the tetel repository at commit 67191f5 ("tet28: pin the census refusal, and make the parity guard real"); the working tree was clean at the start of authoring, and this memo plus its snapshot are the one addition the workspace makes to it. That commit matters beyond pinning: it means TET-28's modification-target machinery — the record type, the refusing verb, the render section, the snapshot re-verification — is in the tree, and this design reads it as implemented precedent rather than as a sibling design document. TET-29 asks for a second required section: any design that transplants a mechanism from another site must carry a premise inventory — donor site, the donor's comment-stated premises transcribed verbatim, and per premise a claim that it holds at the destination — with `check` refusing the shape (section absent, or a premise row citing no claim) and never judging the content. This memo settles what the trigger is, what the record holds, what "transcribed verbatim" can decidably mean, where the refusals fire, and what is printed as uncatchable.

*cites: C1*

The answer, up front. The ticket survives contact with the codebase, but not in its own vocabulary — four reformulations, each argued below. First, the trigger: "any design that transplants" is as undecidable from prose as "a memo's recommendation" was for TET-28, so the trigger is an author-declared transplant record, and the refusal attaches to declarations. Second, and largest: "transcribed verbatim" cannot be a typed field on trust — a premise is refused unless its text is a verbatim substring of one observation's captured output inside the cited donor fact, which converts transcription from a request into a machine guarantee and makes TET-29 the first load-bearing use of the README's supporting-span-selection direction. Third, the refusal the ticket placed at `check` splits across three surfaces: quotation invariants refuse at the verb, completeness refuses at `render --out`, and `check` re-verifies both against the snapshot for documents that never passed through either. Fourth, a composition the ticket left open: the transplant's destination is a citation of a live modification target, so declaring a transplant forces TET-28's census at the landing site. What none of this touches — deliberately — is content: the tool never decides what counts as a premise, whether a selection is deep enough, or whether a discharge claim is true. Its entire effect is to move the violated property from "asserted by no claim at all" into the evidence ledger, where the existing grounding loop can reach it.

*cites: C2, C3, C7, C9, C13*

## The trigger: a declared transplant, for the reasons TET-28 already carries in its shipped code

The ticket's rule as written — "any design or fix that transplants a mechanism from another site must carry a premise-inventory section" — has the same undecidable subject TET-28's ticket had. Nothing in the record model types anything as a transplant; deciding that a fix transplants means either reading the prose for tell-tale language or comparing code across two sites, and both are heuristic reads of content, the class this project has measured dead once (scope.rs's mention-detector flagged a legitimate quotation and missed both real overreaches) and has now shipped a refusal-shaped alternative to once (targets.rs, whose module doc carries the argument as implemented doctrine, not proposal). So the trigger is the same shape: the author declares a transplant as a structured record, the refusal attaches to the declaration, and the memo that transplants without declaring is not detected — it is made visible, by a section that renders its own absence and a non-coverage line that prints the blind spot. This memo does not re-litigate that reasoning; it verifies it transfers, and it does: the one disanalogy — a transplant is an act the design performs, where a modification target is a thing the design names — changes nothing about decidability, because in both cases the undecidable step is deciding from content that the memo is in the rule's scope at all.

## What "transcribed verbatim" must mean: selection, not transcription

This is the ticket's largest hidden decision, and the design departs from the ticket's letter here. "The donor's comment-stated premises, transcribed verbatim" describes an author typing text and promising it is a quotation — an honour system, bolted onto a tool whose central guarantee is that evidence is captured and cannot be typed. Nothing would stop a premise the donor never wrote, or a paraphrase quietly weaker than the original. The decidable replacement: a premise is refused unless its text is a verbatim substring of the cited donor fact's captured output. Both sides of that comparison are tool-controlled bytes — a fact's output can only come from look/run, cannot be supplied by hand, and never changes after mint — so the refusal is a pure containment check with nothing heuristic in it. The author still types, but typing becomes the selection mechanism rather than the trusted act: you cannot invent a premise, only select one from what you captured. This is the README's supporting-span-selection Direction item made load-bearing for the first time, in exactly the narrow place it pays for itself — and note the dependency runs the useful way round: TET-29 needs span selection only for premise rows, so it can ship the mechanism in miniature without committing to span selection at general mint time.

*cites: C3*

Two objections were the reason this could not simply be assumed, and both were settled against the capture code rather than by preference. First, strictness: a donor comment wrapped across lines, with `//` or `*` prefixes and indentation inside it, is in fact a contiguous byte substring of a `look` capture. The plain open stores the file's bytes verbatim — no line numbers, no headers, no reflowing — and the `--lines` mode stores the selected lines re-joined with newlines, normalising CRLF endings and the trailing newline in that mode only; in both modes the relation is defined over the captured string itself, so what a memo can quote is exactly what was captured, never a third spelling. The cost is that the premise appears in the rendered section with its comment syntax intact, which the "never paraphrase" constraint treats as a feature: the reader sees the donor's clause as the donor's file spells it. Stripping the noise would require per-language comment knowledge, the exact coupling scope.rs's "Language-agnostic by construction" section exists to exclude. The two capture modes that genuinely fight containment — grep outputs, whose lines carry `lineno:` prefixes, and whole-search records, whose output is empty — make `look` of the donor file the natural donor capture, and the refusal's diagnostic should say so; the relation itself stays indifferent to observation kind. Whether the motivating premise itself clears this bar is not left to argument — the next paragraph tests it at the source. Second, soundness: a fact's output is the join of its observations' outputs, boundaries unstored, so whole-output containment would accept text straddling the seam between two captures — bytes never contiguous in anything the author saw. The fix is one serde-defaulted per-entry byte-length field on the extent entry, the same compatibility move that added kind and pattern for TET-28: boundaries become reconstructible, the relation tightens to "substring of a single observation's output", and a donor fact minted by an older build is ineligible with the same cheap remedy — look again.

*cites: C4, C5*

The relation was then tested against the motivating case itself rather than a constructed example, by reading the forklift sources at today's HEAD (with read-only git commands). It passes, and the test corrected the ticket in one place. The missed premise — "its parent is remote-known or was walked earlier in this same session" — is contiguous in the raw bytes of the donor file, both as a clause within one line and as the whole seven-line comment with its `//` prefixes, so the refusal admits it with no comment-syntax knowledge anywhere in the tool. But it does not live where the ticket's phrasing suggests: the donor function's doc block never states the insert-before-check discipline or its ordering premise at all — both live in a body comment below the signature, and the ordering constraint the import also depended on sits at a call site in another region of the file. "The donor's comment-stated premises" therefore must not be operationalised as "the donor's doc block". The relation ranges over whatever bytes the author's donor fact captured, and that is the right scope for a second reason: a premise the author knows about but did not capture cannot be selected, so the refusal pressures the capture wider — the donor fact may fold several observations (the function and its call site, say), and a missing premise is fixed by another look, never by typing. One more datum from the same reading: the repaired destination in today's tree states the once-missed condition as a single sentence in its own doc comment, which is concrete evidence that the per-premise discharge obligation — one claim asserting the premise holds at the destination — fits in one gradeable proposition even for the hardest observed case.

## The record: what a transplant holds

A transplant is an append-only record with a new id kind (one enum variant and one counter, the shape Target already added), created and amended through one dispatch shared by CLI and MCP. Its fields are citations and selections, never typed descriptions. The donor site is a citation of exactly one fact — the same single-citation discipline the target verb states, and a fact rather than a path so that "the donor" means a captured extent nobody typed. Each premise row is a verbatim selection from that donor fact's output, immutable once made (a selection of immutable bytes has nothing to revise honestly) and withdrawable with a reason. Each premise is discharged by citing a claim — the destination-holds assertion the ticket asks for — and because the claim verb already refuses a claim citing no fact, the ticket's open question of whether the discharge claim must itself rest on evidence answers itself: yes, by construction, with no new rule. A discharge can be superseded by a later discharge citing a different claim, so a premise whose first destination-holds claim is refuted in grounding is re-dischargeable without withdrawing history. And the destination is a citation of a live modification target: the two tickets compose, because a transplant installs a mechanism at a site the design is thereby telling an implementer to modify. Requiring the destination to be a declared target means declaring a transplant forces the TET-28 census at its landing site — one declaration becomes a forcing function for the other, narrowing TET-28's admitted under-declaration blind spot for precisely the fix-shape that produced the motivating defect. The edge case costs nothing: a green-field destination is censusable today, because the census predicate deliberately accepts a no-match search — a symbol with no occurrences yet is censused by the grep that established it has none.

## Where the refusals fire: verb, then render --out, then check

TET-28 moved its whole refusal to the verb and left render refusal-free. TET-29 cannot copy that placement wholesale, and the reason is a real disanalogy, not taste: a census either exists when the target is declared or it does not, but a premise inventory is built across time. The instrument works by transcribe-first — the author selects the donor's premises before knowing whether each holds at the destination; that confrontation is the mechanism. Refusing an undischarged premise at declaration would demand the destination-holds claim before the premise can exist, inverting the order into answer-first-transcribe-after, and pushing an author who cannot yet discharge a premise toward the quiet exit of never declaring it — the exact "refusing would make the honest case unwritable" failure the project's own discriminator names. So the refusals split by question. The verb refuses everything that is per-record and decidable at creation: a donor fact that does not exist or predates span boundaries, a premise that is not a genuine quotation, a destination that is not a live target, a discharge naming no live claim. Completeness — every premise on every live transplant discharged — is a property of the finished document, and it is refused at `render --out`: the act that writes the reviewable artifact and its snapshot, under the already-pinned policy that a rendered memo is never hand-edited. A memo with a declared-but-unexamined premise fails to come into existence rather than existing and failing; the remedy is singular; a preview render still assembles with undischarged rows marked loudly, so mid-work visibility survives. This makes TET-29 the first refusal on the render path, which is the design's most debatable departure — the alternative of letting the memo render and having only check fail it matches the ticket's letter, but it manufactures exactly the artifact the ticket exists to prevent and then depends on the author running check. Last, check re-verifies the whole shape against the shipped snapshot, both directions since tampering goes both ways, as a machine failure beside uncensused targets; containment is re-checked byte-for-byte from the facts.jsonl the snapshot already ships, so check still runs nothing and fetches nothing. Without a snapshot, transplant rows are human-owed unverifiable — the standing choice for every snapshot-dependent finding.

## What the document shows

The rendered section sits beside the modification-target section and follows its conventions: labels rather than absolute keys, withdrawn records dropped, and — once the workspace has any claim — an empty section that renders as "none declared" rather than disappearing, because the hole is the finding and an absent section would make the same omission invisible. Per live transplant, the reader sees the donor fact and its extent labels, the destination target, and each premise's selected bytes verbatim in a fenced block with the discharging claim's id beside it. One shipped rule is deliberately inverted here: compose.rs refuses to inline captured output because output is unbounded, but a premise is an author-bounded selection, and inlining it is the entire point — the reader must see the donor's clause on the page, spelled the way the donor's file spells it, next to the claim that answers it, or the section degenerates into opaque pointers. Fenced blocks rather than table cells, because a premise legitimately spans lines and a markdown cell cannot carry multi-line text without escaping it, which would break the byte-fidelity the whole design is built on.

*cites: C11*

check's standing non-coverage list exists precisely because a refusal that fired is easily read as coverage it never claimed, and this feature adds six lines to it. An undeclared transplant — no refusal can reach it; the empty section is its only trace. Premises the donor never wrote down — selection ranges over captured text, so a premise living in the donor's structure rather than its comments has nothing to select; the ticket names this limit and the mechanism genuinely has it. Premises outside the captured extent — a donor fact minted from too narrow a look cannot yield a premise from lines it never captured, and the remedy the design offers is wider capture, not typing. Shallow selection — the tool verifies that the selected bytes are the donor's, never that they are all the load-bearing ones; deciding what counts as a premise is design judgment the ticket keeps out of tool reach, and deciding a selection is too small is a truth-check, which this project registered as permanently out of reach. Whether a discharge claim actually addresses its premise, and whether the cited target really is where the mechanism lands — both content; the claim is graded as written by the grounding loop, the linkage by nobody. And a donor comment that is itself wrong — quotation establishes provenance, never truth. On the vacuity risk: the ticket argues it small from its two observed data points — both misses, on its account, were failures to transcribe at all rather than shallow readings of transcribed text — and this design records that as the ticket's premise rather than re-establishing it, adopting the ticket's own discipline of treating the mechanism as a trial to re-examine after two designs, not a law.

*cites: C12*

Per the ticket's account of the FORK-94 trail — which this memo records as the ticket's report rather than re-establishing — the defective remedy was graded `supports` twice, correctly, and was still unsound, because the violated property (audit completeness under the caller's iteration order) was asserted by no claim at all. That situation is the first entry in check's own non-coverage list: dependents that never declared themselves. A grounder grades propositions as written; where there is no proposition, there is nothing to grade, and no number of passes closes the gap. Every piece of this design funnels toward converting that absent proposition into a present one. The premise row forces the donor's condition onto the page as captured bytes; the discharge obligation forces a claim that the condition holds at the destination; and that claim is a claim like any other — resting on facts by construction, entering the evidence ledger, graded by the next grounding pass, revisable and then out of proof until regraded. The tool never judges whether it is true. It refuses only the shape in which the question goes unasked. And the hardest observed case shows the converted claim fits in one sentence: today's repaired destination states the once-missed condition in a single doc-comment sentence — so the obligation this design imposes per premise is one gradeable proposition, not an essay.

## Implementation surface, and what this memo does not decide

Every component extends a mechanism already in the tree, and none crosses a doctrinal line: one serde-defaulted per-entry output-length field on the extent record (the compatibility move that added kind and pattern for TET-28, with the same absent-means-ineligible reading — a legacy donor fact is re-looked, never guessed about); one new record kind, counter, and id prefix; a transplants.jsonl written by one CLI/MCP-shared dispatch and shipped by one new line in the snapshot's deliberately-enumerated file list, whose targets.jsonl entry already documents why a record log must ship; one rendered section; one completeness refusal on the render --out path; one snapshot re-verification beside the census one; and the six non-coverage lines. Nothing parses any programming language — the containment check is byte comparison, indifferent to what the bytes mean — nothing is re-run or fetched at check time, and no score or document-level verdict appears anywhere. What this memo deliberately does not decide: the premise-row id spelling and event grammar beyond append-only-with-withdraw; whether span selection should later generalise to ordinary mint-time notes, which stays a Direction item with this feature as its first measurement; and any widening of the trigger toward detecting undeclared transplants, which the measured evidence against prose-reading refusals rules out now for the same reason it did for TET-28.

## Modification targets

None declared. A target is a symbol this design tells an implementer to modify; declaring one requires a search of the whole worktree for it. Nothing forces a recommendation to be declared, so an empty section is not evidence that none exist.

## Transplants

None declared. A transplant installs a mechanism taken from another site; declaring one requires selecting the donor's stated premises from captured output and answering each at the destination. Nothing forces a transplant to be declared, so an empty section is not evidence that none exist.
