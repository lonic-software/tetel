tet28-modification-target-census · C5

later graded supports
The claim, as it stood at first render — 2 fact(s) cited

A census check cannot be built on labels, and the record model already shows the right way to extend the schema. At mint time only key, label, world_root and world_state survive into an ExtentEntry — the observation's kind is dropped, and the grep pattern exists only inside a display label, where an author-chosen pattern containing " in " or "(grep: " would make parsing ambiguous. The census therefore needs the new root-level search entry to carry two structured fields into ExtentEntry — the observation kind and the search pattern — following the exact precedent world_root set: #[serde(default)], with the empty value read as "predates the field, not eligible" rather than guessed about. Legacy facts can then never satisfy a census requirement, whose remedy is precisely to re-run the grep under the new capture. The snapshot already ships facts.jsonl with full extent entries, so check reads these fields from files every snapshot already contains; and because no surface lets an author supply an extent by hand, both sides of the rooting comparison and the pattern are tool-captured by construction.

tet29-imported-mechanism-premises · C3

later graded supports
The claim, as it stood at first render — 2 fact(s) cited

"Transcribed verbatim" cannot be an honour-system field, and does not need to be: the decidable relation is that a premise's text is refused unless it is a verbatim substring of the cited donor fact's captured output. Both sides of that comparison are Strings the tool controls — a fact's output is produced only by look/run (file bytes read verbatim by look_path, grep match lines, a process's merged stream), no authoring surface lets anyone supply output by hand, and output is immutable after mint — so substring containment is a pure byte-level comparison with no normalisation step owned by the check. Typing is the selection mechanism, not the trust: the author types the premise, but a typed premise the donor never wrote fails containment and is refused at the verb. This is exactly the README's Direction item for supporting-span selection ("refused unless it is a verbatim substring of a cited fact — the author cannot type an extent, and here could not invent support, only select it"), and TET-29 is the first place it becomes load-bearing rather than roadmap.

The rendered section follows compose.rs's shipped conventions with one deliberate difference. A "## Transplants" section renders beside the modification-target section: per live transplant, the donor fact id with its extent labels (labels, never absolute keys — the committed-document rule), the destination target id and symbol, and one entry per live premise carrying the selected text verbatim in a fenced block with the discharging claim id beside it; withdrawn transplants and premises are dropped, and once any claim exists the section renders even when empty ("none declared"), because the hole is the finding — the same visibility answer to under-declaration the target section shipped. tet29-imported-mechanism-premises · C8

later graded supports
The claim, as it stood at first render — 2 fact(s) cited

An undischarged premise must be a legal workspace state, so the ticket's refusal cannot all move to the verb the way TET-28's did. The instrument works by transcribe-first: the author selects the donor's premises before knowing whether each holds at the destination — the confrontation the section exists to force. Refusing a premise row that cites no claim at declaration time would demand the destination-holds claim exist before the premise can be recorded, inverting that order (answer first, transcribe after) and pushing an author who cannot yet discharge a premise toward not declaring it at all — the same "refusing would make the honest case unwritable to catch the dishonest one" failure scope.rs's discriminator names. TET-28 never faced this because a census either exists or does not; a premise inventory is built across time. So the workspace invariant enforced at the verb is only "every premise is a genuine quotation of the cited donor's capture" (plus: donor fact exists and carries span boundaries, destination target exists and is live, a discharge cites an existing live claim); "every premise is discharged" is not a workspace invariant at all — it is a property of the finished document.

tet28-modification-target-census · C7

later graded supports
The claim, as it stood at first render — 1 fact(s) cited

The decidable trigger is declaration (candidate 1): a modification target is a structured record the author creates — a symbol string plus a fact citation — and the refusal fires only on a declared target whose cited fact carries no qualifying census entry. This sits inside the machine partition's own stated principle, that machine failures are "objective contradictions between a document and the record it claims to rest on, decidable without a human": a target row is exactly a pointer at evidence, and "you did not point at your evidence" is the README's own example of a decidable question. The refusal's remedy is singular — run the workspace-rooted grep for that symbol, mint the fact, cite it (or withdraw the target) — so refusal rather than report is the right disposition for the declared-but-uncensused case, by the same discriminator under which scope.rs chose report: there, only a person can tell context from conclusion; here, nothing is left to tell.

The conclusion

Eight of twelve look like real findings on claims that a grounding pass let through. If that holds, the residual false-positive rate is not 19% — the test is scoring the verifier against graders who are themselves fallible, and disagreement with a grader is not the same as error. On this sample the verifier is right more often than the graders were.

The dominant remaining defect is one thing, and it is specific: two of twelve read a proposal as a description. A design memo asserts both what the code does today and what this design will make it do, and only the first is checkable against captured bytes. The verifier has no way to tell them apart, so it reports the absence of a section the design exists to add as a contradiction. That is a prompt problem, not a idea problem, and it is the next thing to fix.

The gate still fails: twelve flags against a kill threshold of seven. But it began at 53.
